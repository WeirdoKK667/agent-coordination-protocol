# 可信度重议协议（v6 强制重议）

> 来自 Stripe RFS 模型。每 4 周或每 milestone 触发一次。main 召集，相关 agent 投票，可修改可信度条款但不可删硬条款。

## 触发条件

满足任一即触发：
- 每 4 周（默认重议周期）
- 每个 milestone 结束
- 验证岗触发重议请求（验收通过率 < 90%）
- main 主动决定重议（健康度告警响应方式之一）

## 召集流程

```
1. main 在 roles/decisions/ 创建 credibility-revisit-<YYYY-MM-DD>.md
2. 列出本次重议范围：
   - 修改项（可修改的：通过阈值 / 命令参数 / 失败容忍）
   - 保留项（不可修改的硬条款）
3. 召集相关 agent：
   - main（必到）
   - 验证岗（必到，若存在）
   - 实现岗（相关模块）
   - 用户（如有重大变更）
4. 投票：每人一票；平票时 main 决定
```

## 可修改项

- **通过判据**：如 PASS 阈值从 100% 调到 95%（+5% 容忍）
- **命令参数**：加新测试场景 / 改超时 / 改并发度
- **失败容忍策略**：哪些失败可自动重试 / 哪些必须人工
- **重议周期**：从 4 周调到 2 周或 8 周（但需 ≥ 2 周）

## 不可修改项（红线）

- **必须可复现**：一条命令 + 工作目录 + 完整参数 + `--` 分隔符
- **必须带计数**：PASS/FAIL 输出
- **必须留痕**：失败日志落盘
- **必须报远程 commit hash**：本地 commit 无效

任何试图删除不可修改项的提议**直接拒绝**（票数为 0）。

## 留痕格式

```markdown
# 可信度重议记录（<YYYY-MM-DD>）

## 召集人
<main / co-main>

## 参与投票
- <岗名 1>：赞成 / 反对 / 弃权
- <岗名 2>：赞成 / 反对 / 弃权

## 修改项

| 项 | 修改前 | 修改后 | 票数 |
|---|---|---|---|
| 通过阈值 | 100% | 95% | 3 赞成 / 0 反对 |
| 命令参数 | --autotest | --autotest --include-integration | 2 赞成 / 1 反对 |
| ... |  |  |  |

## 保留项（不可修改）

- [ ] 一条命令可复现（含 `--` 分隔符）
- [ ] 输出带计数
- [ ] 失败留痕
- [ ] 报远程 commit hash

## 下次重议日

<YYYY-MM-DD>（4 周后或下个 milestone）
```

---

## 与健康度挂钩的关系

- 健康度告警触发时，main 的响应选项之一就是"调用重议"
- 重议结论必须反馈到 health-checklist.md 的阈值
- 重议留痕文件本身要被健康度仪表盘扫描（防止遗漏）

---

## 不要做的事

- 不要跳过重议周期——4 周强制一次，不可延期
- 不要删除硬条款——票数为 0 自动拒绝
- 不要让单方面决定修改——必须走投票
- 不要让重议留痕散落——必须落 `roles/decisions/credibility-revisit-<date>.md`
