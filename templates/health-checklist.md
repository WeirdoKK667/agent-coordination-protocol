# CHAOSS 健康度检查清单（v6 健康度挂钩）

> 自动算 + 阈值告警 + main 必响应。挂钩 templates/credibility-revisit-protocol.md 的重议周期。

## CHAOSS 指标（自动计算）

### 项目级

| 指标 | 计算方式 | 健康阈值 | 告警条件 |
|---|---|---|---|
| **bus factor** | 每个模块的可接替者数量 | ≥ 2 / 模块 | < 2 → 触发招人或拆分 |
| **贡献者变更率** | 周新增 / 周离开贡献者数 | ±10% / 周 | > 30% → 触发分权评估 |
| **issue 解决时间（中位数）** | P50 close 时间 | < 7 天 | > 14 天 → 触发流程审查 |
| **PR review 时间（中位数）** | P50 review→merge 时间 | < 3 天 | > 7 天 → 触发流程审查 |

### main 专属（v6 新）

| 指标 | 计算方式 | 健康阈值 | 告警条件 |
|---|---|---|---|
| **main 负载率** | main 本周处理 PR/任务数 | ≤ X / 4 周（X 由项目规模决定） | > X → 触发分权 / 招 co-main / 暂停派发 |
| **main 决策间隔** | 平均决策响应时间 | < 24h | > 72h → 触发接班人评估 |

### 验证岗专属（招出时启用）

| 指标 | 计算方式 | 健康阈值 | 告警条件 |
|---|---|---|---|
| **验收通过率** | 周验收 pass 数 / 总数 | ≥ 95% | < 90% → 触发实现岗 review + 重议可信度条款 |
| **失败留痕完整性** | 失败用例含日志 + commit hash 比例 | 100% | < 100% → 触发验证岗培训 |

## 初始化流程

```
1. 招出验证岗后立即初始化
2. 把上述阈值写到 roles/health/baseline.md
3. 设置自动计算脚本（cron / GitHub Action）
4. 设置告警接收人：main
5. 设置重议日：每 4 周或每 milestone
```

## 告警响应（main 必响应，不不可绕过）

收到告警后的响应方式（任选）：

1. **临时挂起**：暂停派发新任务，集中处理告警项
2. **触发分权**：招 co-main / 委员会
3. **招新人**：在登记表加新岗、走招聘流程
4. **调用重议**：触发 templates/credibility-revisit-protocol.md，重新评估条款

**红线**：
- 告警不可静默忽略（必须留响应记录）
- 告警不可关闭（除非对应问题已实际解决）
- 告警不可无理由延期（延期必须写明截止日期）

## 不要做的事

- 不要让告警自动关闭——必须 main 显式确认
- 不要无限提高阈值（bus factor 从 2 调到 5 是反 Conway）
- 不要在告警期间派新任务——先处理告警
