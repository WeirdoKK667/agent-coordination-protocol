# 登记表变更 PR 模板（v6 协议即代码）

> 适用于：占位登记表 / 任务清单 / 可信度条款 / 健康度阈值 / 身份卡的任何变更。GitHub PR 模板，强制填写。

## PR 标题

`<type>: <scope> — <一句话摘要>`

type 取值：
- `add` 新增岗 / 新增任务 / 新增条款
- `remove` 撤销岗 / 删除任务 / 删除条款
- `update` 修改岗职责 / 修改任务 / 修改阈值
- `rotate` 轮换岗（如 co-main 交接）

## PR 描述模板

```markdown
## 变更类型

[ ] add  [ ] remove  [ ] update  [ ] rotate

## 涉及范围

- 占位登记表：是 / 否
- 任务清单：是 / 否
- 可信度条款：是 / 否
- 健康度阈值：是 / 否
- 身份卡（含 id-card-main-designer.md）：是 / 否

## 变更前

| 字段 | 旧值 |
|---|---|
|  |  |

## 变更后

| 字段 | 新值 |
|---|---|
|  |  |

## 是否突破 ≤ 6 硬上限

[ ] 否
[ ] 是——理由：<必填，写明为何本项目需要超过 6 张卡>

## 是否触发健康度告警

[ ] 否
[ ] 是——已确认 main 响应方式：<挂起 / 分权 / 招人 / 重议>

## Reviewer 检查清单

- [ ] 不破坏八条原则
- [ ] 不引入静默突破 ≤ 6 硬上限
- [ ] 不绕过健康度告警
- [ ] 不删除可信度硬条款（重议只可修改可修改项）
- [ ] 反向兼容（旧岗的 身份卡仍有效）

## 测试

- [ ] 已跑健康度仪表盘（无新增告警）
- [ ] 已验证登记表与 身份卡交叉引用一致
- [ ] 已更新 README / docs（如有）
```

---

## 强制审查

**Reviewer 要求**：
- 任何变更都需要至少 1 个 reviewer approve
- 突破 ≤ 6 硬上限的变更需要 2 个 reviewer（co-main 或可信岗）
- 删除可信度硬条款的变更**直接拒绝**（红线，不可删）

---

## 不要做的事

- 不要绕过 PR 直接 push 到 .claude/coordination/
- 不要让单方面决定突破 ≤ 6 硬上限
- 不要删除可信度硬条款（即使重议也不行）
- 不要让健康度告警未响应就合 PR
