# 派发命令模板（形式 A：用户复制粘贴）

> 用户在不同 IDE / 不同会话里手动操作时使用。main 生成可粘贴的命令文本。

## 命令文本模板

```markdown
## 派发任务 — <任务名>

**身份牌**：id-card-<昵称>.md（开工前先读，按 read 最小契约执行）

**任务描述**：
<一段话讲清任务目标 / 边界 / 交付物>

**开工前核对清单**（main-designer 派发前必查 5 项，**不是可选项**）：
- [ ] 必读现状文件：<列具体文件，逐个真读过，不要按规范推断>
- [ ] 必查基线数字：<跑基线测试拿当前值，写到 §验收>
- [ ] 必查红线文件状态：<已归档 vs 进行中，避免派已闭环的单>
- [ ] 必查文件所有权清单：<含测试前置数据文件>
- [ ] 必查本需求的历史派发单：<同一 REQ 是否已有单闭环过>

> 实战 14+ 处翻车全部出在派发前没做实地核验。

**测试员模式要求**：
main-designer 指定 implementer 走 A / B / C 中哪种方式跑测试：
- **A**：implementer 自跑测试 —— 实测稳定 120s ± 30s（10 次），**默认用这个**
- **B**：派独立验证岗 subagent 跑 —— 实测 1359s（≈ 11× A）。⚠ 子进程卡死时 subagent 既不能报告也不能 abort，只能等 timeout 兜底（实测卡死 9 分钟）
- **C**：用 Agent 工具派 subagent 跑 —— 未采数据

本单指定方式：<A / B / C>

implementer 采字段：开始时间 / 命令 / PASS-FAIL 数 / 结束时间 / 总耗时 / subagent 启停耗时 / 主观感受
写进 handoff 的 §测试员耗时 段。

**串行 / 并行**：
- 本单与 <单号> 改同一批文件 → 严格串行（commit + push + handoff 后再接下一单）
- 文件族不重叠 → 可跨线并行

**任务凭证**：
- REQ 单：REQ-<id>.md
- DESIGN 文档：DESIGN-<id>.md（如有）

**read 最小契约**（缩小版）：
- 必读：本卡 + REQ 单 + <具体改动文件> + <断言对应测试段>
- 显式无需读：<其他岗设计稿 / 归档 / 视图层>

**红线**：
- 不写 `<永久不碰的文件>`
- 不调用 `<未授权的跨模块 API>`

**交工凭证**：
- git push + 实跑输出（PASS/FAIL 计数）
- 报 commit hash + remote branch
- 回填 REQ 单"已完成 + commit hash + 验收岗"

**交接**：
- 完成后按 templates/handoff-checklist.md 交给 <下一岗>

---

> 操作：复制本块粘贴到目标 agent 会话
```

---

## main 渲染时的强制行

```markdown
**身份牌**：id-card-<昵称>.md（开工前先读，按 read 最小契约执行）
```

这是 §三 末认领协议硬条款，不能省。

---

## 不要做的事

- 不要省"身份牌"行——target agent 没卡就开工会越界
- 不要把所有 read 契约全塞进去——只塞本任务相关的（缩小版）
- 不要把任务描述写得过简——target agent 必须有足够上下文
