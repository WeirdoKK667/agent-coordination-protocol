# CHAOSS 健康度指标挂钩（references/health-metrics.md）

> v6 原则 8。自动算 + 阈值告警 + main 必响应。

## 指标分类

### 项目级（CHAOSS 标准指标）

| 指标 | 计算方式 | 健康阈值 | 告警条件 |
|---|---|---|---|
| bus factor | 每个模块可接替者数量 | ≥ 2 / 模块 | < 2 → 招人或拆分 |
| 贡献者变更率 | 周新增 / 周离开贡献者数 | ±10% / 周 | > 30% → 触发分权 |
| issue 解决时间 P50 | P50 close 时间 | < 7 天 | > 14 天 → 流程审查 |
| PR review 时间 P50 | P50 review→merge | < 3 天 | > 7 天 → 流程审查 |

### main 专属（v6 新）

| 指标 | 计算方式 | 健康阈值 | 告警条件 |
|---|---|---|---|
| main 负载率 | main 本周 PR/任务数 | ≤ X / 4 周（X 见下） | > X → 分权 / co-main / 暂停 |
| main 决策间隔 | 平均决策响应时间 | < 24h | > 72h → 接班人评估 |

**main 负载上限 X 经验值**：
- 小作坊：≤ 5 / 4 周
- 中型：≤ 15 / 4 周
- 大型：≤ 25 / 4 周
- 超大：≤ 40 / 4 周（且必须有 co-main）

### 验证岗专属

| 指标 | 计算方式 | 健康阈值 | 告警条件 |
|---|---|---|---|
| 验收通过率 | 周 pass / 总数 | ≥ 95% | < 90% → 触发实现 review + 重议 |
| 失败留痕完整性 | 失败用例含日志 + hash 比例 | 100% | < 100% → 触发培训 |

## 初始化流程

```
1. 招出验证岗后立即初始化
2. 把阈值写到 roles/health/baseline.md
3. 设置自动计算：
   - cron（小型）
   - GitHub Action（推荐）
   - CHAOSS 项目 Augur（大型）
4. 设置告警接收人：main
5. 设置重议日：每 4 周或每 milestone
```

## 告警响应（main 必响应）

收到告警后的响应方式（任选）：

1. **临时挂起**：暂停派发新任务，集中处理告警项
2. **触发分权**：招 co-main / 委员会
3. **招新人**：在登记表加新岗、走招聘流程
4. **调用重议**：触发 credibility-revisit-protocol.md

## 与重议机制的关系

- 重议周期 = 健康度审视周期（每 4 周 / 每 milestone）
- 重议结论必须反馈到本文件的阈值
- 告警触发可选择"调用重议"作为响应方式
